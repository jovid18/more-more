# apps/web

클라이언트. 서버 스냅샷을 받아 그리고, 틱 사이를 보간한다.

## 실행

서버와 클라이언트를 각각 띄운다.

```sh
cd apps/server && go run ./cmd/server   # :8080
pnpm dev                                # :5173 (레포 루트에서)
```

`Space` 또는 화면 아래 버튼으로 방향을 바꾼다. 탭을 여러 개 열면 그만큼 플레이어가 는다.

개발 서버는 `/healthz`와 `/ws`를 `http://localhost:8080`으로 프록시한다. 서버를 다른
포트로 띄웠다면 `SERVER_ORIGIN=http://127.0.0.1:9000 pnpm dev`.

프록시를 두는 이유는 클라이언트가 개발·배포에서 똑같은 상대 경로를 쓰게 하려는 것이다.
`ws://localhost:8080/ws` 같은 절대 주소를 코드에 적으면 배포 때 갈라진다.

> `localhost:8080`에 다른 것이 이미 떠 있으면 프록시가 그쪽으로 간다. 특히 Node가
> `localhost`를 IPv6(`::1`)로 먼저 풀기 때문에, IPv4에만 바인딩한 서버는 조용히 지나친다.
> 그럴 때는 `SERVER_ORIGIN`에 `127.0.0.1`을 명시할 것.

## 색

플레이어 색은 ID에서 황금각(137.5°)씩 돌려 만든다. `id * 30` 같은 식이면 12명마다
같은 색이 돌아오지만, 황금각은 인접한 ID끼리도 확실히 갈린다.

땅은 주인의 색을 밝기만 낮춰 칠한다 — 구간이 가장 어둡고, 역이 중간, 말이 가장
밝다. 색상이 같아서 누구 땅인지 바로 읽히면서도, 지도 위에서 말이 묻히지 않는다.

**소유는 보간하지 않는다.** 한 틱에 딱 바뀌는 값이라 섞으면 색만 흐려진다. 대신
소유 배열의 참조가 바뀌었을 때만 다시 칠해서, 매 프레임 수백 개 float을 쓰지 않는다.

## 보간

서버는 초당 두 번만 말한다. 그대로 그리면 화면이 뚝뚝 끊기므로, 직전 틱과 최신 틱의
위치를 구해 그 사이를 시간에 맞춰 훑는다. 화면은 항상 한 틱만큼 과거이고, 그 대가로
60fps가 나온다 — 판정은 어차피 서버가 하므로 잃는 것이 없다.

**격자 값이 아니라 월드 좌표에서 섞는 것이 요점이다.** 구간을 갈아타는 순간에도 그냥
맞는다: 직전이 A→B의 2/3 지점이고 최신이 B→C의 0 지점(=B역)이면, 두 점을 잇는
직선이 A→B의 남은 1/3과 정확히 겹친다. `progress` 값을 섞었다면 2에서 0으로 떨어지며
플레이어가 역으로 되감겼을 것이다.

방향 전환도 마찬가지다. 서버가 뒤집을 때 `progress`까지 함께 뒤집어 주므로 뒤집기
전후의 월드 좌표가 같고, 그래서 화면이 튀지 않는다. 이 두 경우가 `interpolate.test.ts`에
그대로 들어 있다.

## 3D는 아직 이르다

지금 지도는 평면이고 카메라도 거의 수직으로 내려다본다. three.js가 값을 하는 것은
가지 노선이 붙어 노선도가 겹치기 시작할 때다 — 노선별 z축 분리, 루프로 가둔 영역의
융기. 야마노테 하나를 그리는 동안에는 Canvas 2D로도 충분하고, 지금 three.js를 쓰는
것은 그때 갈아엎지 않기 위해서다.

## 아직 없는 것

- 역 이름 표시. 서버는 한자·로마자를 모두 보내지만 화면에는 아직 안 그린다
- 지도 조작(줌·팬). 30역이 한 화면에 들어와서 급하지 않다
- 골드·점수. 서버에 경제가 생기면 HUD로 들어온다
- 누가 누구인지 보여주는 목록. 지금은 색으로만 갈린다
