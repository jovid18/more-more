# more-more — 도쿄 지하철 땅따먹기

Go 동시성 학습용 실시간 게임 서버 (『Concurrency in Go』 실전 적용)

## 컨셉

도쿄 지하철 그래프에서 여러 유저가 노선을 돌며 땅을 따먹고, 요지를 수호해 골드를 버는 실시간 전략 게임.

## 개발

|               |                                    |
| ------------- | ---------------------------------- |
| `apps/server` | Go. 권위적 게임 서버               |
| `apps/web`    | Vite + React + three.js 클라이언트 |

```sh
# 클론마다 한 번
git config core.hooksPath .githooks
git config pull.ff only

pnpm install

pnpm dev                       # 클라이언트 :5173 (/ws는 :8080으로 프록시)
cd apps/server && go run ./cmd/server   # 서버 :8080
```

검증은 [CLAUDE.md](./CLAUDE.md)에 정리돼 있다. `main`은 GitHub 룰셋으로 보호되어 있어 PR을 거쳐야 하고, `Server`·`Web` 체크가 통과해야 머지된다.

## 서버 구조 (핵심 = 동시성)

- **권위적(Authoritative)**: 클라는 입력만 전송, 모든 계산·판정은 서버가 함 (치트 방지)
- **틱 기반**: `time.Ticker`로 주기적 시뮬레이션. **1~2Hz 추천** (반응속도 X, 전략 게임)
- **단일 상태 소유 goroutine**: 게임 상태를 goroutine 하나가 통째로 소유 → mutex 없음
  - 입력: 여러 연결 → 채널 **fan-in**
  - 출력: 스냅샷 → 전원 **fan-out** broadcast
  - `context` 취소 / graceful shutdown으로 이탈·종료 처리
- race condition이 구조적으로 불가능 (판정이 한 곳에서 순서대로)

## 이동 모델

- 순간이동 ❌ / **구간별 N틱에 걸쳐 이동** ⭕
- 서버는 **진행도 정수**로 이산 처리: `{From, To, Progress, NeedTicks}` (좌표 계산 X)
- 매 틱 `Progress++`, 도달 시 점령·경합 판정
- 부드러운 움직임은 **클라이언트가 보간(interpolate)** → 서버 느려도 화면은 매끄러움
- MVP: NeedTicks 전부 고정(예: 3틱)

## 땅 / 거점

- **엣지(구간) = 땅**: 지나가면 내 색으로 칠함
- **역 = 거점**: 수호 시 골드. **차수(연결 노선 수) 높은 허브일수록 가치 ↑**
- 경합: 같은 역 동시 도착 시 단일 goroutine이 순서대로 판정

## 그래프 지형 = 전략 지도

- 실제 도쿄 = **밀집 코어(루프+격자) + 방사형 가지(spoke)**
- **가지 끝(리프 노드)** = 고위험 고수익. 코어 연결점(**단절점/articulation point**)만 뺏기면 통째로 무효화
- **연결성 규칙**: 내 땅은 본진과 연결돼야 유효. BFS/DFS로 매 틱 검사
  - MVP(야마노테 루프)엔 생략, 가지 노선 추가 시 투입

## 루프 룰 (검토 완료)

- 루프 완성 = **소유권 뺏기 불가** (단, 통과는 허용 — "접근 금지"는 맵을 두 동강 내므로 X)
- 영구 잠금 ❌ → **유지 비용**(주기적 재순회 등)으로 교착 방지
- **루프 안에 가치 건물 가두면 보너스** ← 루프의 존재 이유 & 웅크리기 방지책
- 랜덤 강제이동 ❌ → 그래프 사이클 희소성(circuit rank = E−V+1) + 건물 보너스가 정체를 알아서 완화

## MVP 로드맵

1. 야마노테선(순환·30역) 그래프 + 이동 (틱 루프 + fan-in/out 뼈대)
2. 점령(색칠) + 경합 판정
3. 경제(소유 역당 골드) + 건물 수호 보너스
4. 승리 조건 + graceful shutdown + 재접속
5. (선택) 웹 캔버스 시각화 + 클라 보간

## 시작 규모

- 노선 **야마노테 하나**로 시작 → 나중에 가지 노선 확장
- 시각화는 웹 캔버스(점 찍기) 또는 초기엔 CLI/로그
